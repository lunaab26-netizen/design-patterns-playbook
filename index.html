Creational

05 patterns

These control how objects come into existence. Reach for them when construction is expensive, conditional, or needs to stay decoupled from the code that uses the result.

01

Singleton

use sparingly

Intent: guarantee exactly one instance of a class and give it a single, global access point.

Reach for it when
  • One shared resource must be coordinated — a connection pool, a config registry, a logger sink.
  • Duplicate instances would cause real harm (two writers to the same file).
Cost
  • Hidden global state makes tests order-dependent.
  • Hard to parallelise and to mock.
python
class Config:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
            cls._instance.settings = {"env": "prod", "retries": 3}
        return cls._instance

cfg = Config()
assert Config() is cfg          # same object, every time
print(cfg.settings["env"])      # prod
Watch outIn Python a module-level instance (config = Config()) is usually the better answer — it is a singleton the language already enforces. Use the class form only when you need lazy construction.
02

Factory Method

everyday

Intent: let a function or subclass decide which concrete class to instantiate, so callers depend on an interface rather than a constructor.

Reach for it when
  • Callers would otherwise write if fmt == "csv": … elif ….
  • New variants should be addable without editing call sites.
Cost
  • One more indirection to trace when debugging.
  • Overkill when there is only ever one implementation.
python
from abc import ABC, abstractmethod
import json

class Exporter(ABC):
    @abstractmethod
    def export(self, rows): ...

class CsvExporter(Exporter):
    def export(self, rows):
        return "\n".join(",".join(map(str, r)) for r in rows)

class JsonExporter(Exporter):
    def export(self, rows):
        return json.dumps(rows)

def make_exporter(fmt: str) -> Exporter:
    registry = {"csv": CsvExporter, "json": JsonExporter}
    if fmt not in registry:
        raise ValueError(f"unknown format: {fmt}")
    return registry[fmt]()

print(make_exporter("csv").export([(1, "a"), (2, "b")]))
03

Abstract Factory

families

Intent: create whole families of related objects that must be used together, without naming their concrete classes.

Reach for it when
  • Products come in matched sets — a dark theme's button, input and modal.
  • Mixing products from two families would be a bug.
Cost
  • Adding a new product kind touches every factory.
  • More types than a plain factory method.
python
from abc import ABC, abstractmethod

class Button(ABC):
    @abstractmethod
    def render(self) -> str: ...

class DarkButton(Button):
    def render(self): return "[ Dark Button ]"

class LightButton(Button):
    def render(self): return "[ Light Button ]"

class ThemeFactory(ABC):
    @abstractmethod
    def button(self) -> Button: ...

class DarkTheme(ThemeFactory):
    def button(self): return DarkButton()

class LightTheme(ThemeFactory):
    def button(self): return LightButton()

def build_ui(factory: ThemeFactory) -> str:
    return factory.button().render()   # never names a concrete class

print(build_ui(DarkTheme()))   # [ Dark Button ]
04

Builder

everyday

Intent: construct a complex object step by step, so the same process can produce different representations and no half-built object ever escapes.

Reach for it when
  • A constructor would need 6+ parameters, many optional.
  • Construction has an order or validation that must hold.
Cost
  • An extra class per built type.
  • Mutable builder is not thread-safe unless you copy per build.
python
class QueryBuilder:
    def __init__(self):
        self._select = "*"
        self._where = []
        self._limit = None

    def select(self, *cols):
        self._select = ", ".join(cols)
        return self

    def where(self, cond):
        self._where.append(cond)
        return self

    def limit(self, n):
        self._limit = n
        return self

    def build(self) -> str:
        sql = f"SELECT {self._select} FROM orders"
        if self._where:
            sql += " WHERE " + " AND ".join(self._where)
        if self._limit:
            sql += f" LIMIT {self._limit}"
        return sql

q = (QueryBuilder()
     .select("id", "total")
     .where("status = 'paid'")
     .where("total > 100")
     .limit(50)
     .build())
print(q)
05

Prototype

copying

Intent: create new objects by cloning an existing configured instance instead of re-running its construction.

Reach for it when
  • Construction is expensive (parsing, network, heavy defaults).
  • You need many near-identical variants of a configured object.
Cost
  • Deep vs shallow copy is a real correctness trap.
  • Cyclic references need explicit handling.
python
import copy

class Document:
    def __init__(self, title, blocks):
        self.title = title
        self.blocks = blocks

    def clone(self):
        return copy.deepcopy(self)   # nested blocks are copied too

base = Document("Quarterly Report", [{"type": "h1", "text": "Q3"}])

draft = base.clone()
draft.blocks.append({"type": "p", "text": "Revenue up 12%"})

print(len(base.blocks))    # 1  — original untouched
print(len(draft.blocks))   # 2
Watch outcopy.copy() shares the nested list — mutating the clone would silently mutate the original. Use deepcopy unless you have proven sharing is safe.

Structural

06 patterns

These control how objects are composed. They let you add behaviour, hide complexity, or make incompatible things fit together — without rewriting what already works.

06

Adapter

everyday

Intent: convert one interface into another that the caller expects, so incompatible code can collaborate.

Reach for it when
  • Integrating a third-party SDK or legacy module you cannot change.
  • You want to swap vendors behind a stable internal interface.
Cost
  • One more layer to step through.
  • Leaky adapters expose vendor quirks anyway.
python
class LegacyPrinter:                 # cannot be modified
    def print_old(self, text):
        print(f"[legacy] {text}")

class Printer:                       # what our code expects
    def print(self, text: str) -> None: ...

class PrinterAdapter(Printer):
    def __init__(self, legacy: LegacyPrinter):
        self._legacy = legacy

    def print(self, text: str) -> None:
        self._legacy.print_old(text.upper())

def send_receipt(printer: Printer):
    printer.print("order 1042 confirmed")

send_receipt(PrinterAdapter(LegacyPrinter()))
07

Decorator

everyday

Intent: attach responsibilities to an object at runtime by wrapping it, instead of subclassing every combination.

Reach for it when
  • Cross-cutting concerns: retry, cache, timing, auth, logging.
  • Combinations would explode into TimedCachedRetryClient classes.
Cost
  • Deep stacks are hard to read in a traceback.
  • Order of wrapping changes behaviour — document it.
python
import functools, time

def timed(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            ms = (time.perf_counter() - start) * 1000
            print(f"{fn.__name__} took {ms:.1f}ms")
    return wrapper

def retried(times=3):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return fn(*args, **kwargs)
                except Exception:
                    if attempt == times:
                        raise
        return wrapper
    return deco

@timed
@retried(times=3)
def fetch_report(order_id):
    return {"id": order_id, "status": "ok"}

fetch_report(1042)
Watch outDecorators apply bottom-up: @timed above @retried means the timer measures all three attempts, not each one. Swap them if you want per-attempt timing.
08

Facade

simplify

Intent: give a complex subsystem one small, coherent entry point, so most callers never touch its internals.

Reach for it when
  • Callers repeat the same 5-step dance across the codebase.
  • You want to expose a stable API over a messy library.
Cost
  • Can become a god object if it keeps growing.
  • Power users still need the raw subsystem — keep it reachable.
python
class AudioExtractor:
    def extract(self, path): return f"audio<{path}>"

class CodecFactory:
    def for_format(self, fmt): return f"codec:{fmt}"

class Encoder:
    def __init__(self, codec): self.codec = codec
    def encode(self, audio): return f"{self.codec}|{audio}"

class VideoConverter:                      # the facade
    def convert(self, path: str, fmt: str) -> str:
        audio = AudioExtractor().extract(path)
        codec = CodecFactory().for_format(fmt)
        return Encoder(codec).encode(audio)

# caller sees one method instead of three collaborating classes
print(VideoConverter().convert("talk.mp4", "ogg"))
09

Proxy

control access

Intent: stand in for another object to control access to it — lazily, cheaply, or with a permission check.

Reach for it when
  • An object is expensive to create and may never be used.
  • You need caching, access checks, or a remote stand-in.
Cost
  • Same interface as the real thing — easy to confuse the two.
  • Cache invalidation becomes your problem.
python
class RealImage:
    def __init__(self, path):
        self.path = path
        print(f"loading {path} from disk…")   # expensive

    def display(self):
        return f"showing {self.path}"

class LazyImage:                              # proxy
    def __init__(self, path):
        self.path = path
        self._real = None

    def display(self):
        if self._real is None:
            self._real = RealImage(self.path)  # built on first use
        return self._real.display()

img = LazyImage("cover.png")   # nothing loaded yet
print(img.display())           # loads, then shows
print(img.display())           # reuses the instance
10

Composite

trees

Intent: compose objects into tree structures and treat individual leaves and whole branches through the same interface.

Reach for it when
  • Data is naturally a tree: files, UI widgets, org charts, ASTs.
  • Callers should not care whether they hold one node or a subtree.
Cost
  • Over-general interface: leaves must stub out child methods.
  • Recursion depth is a real limit on deep trees.
python
class Node:
    def size(self) -> int: ...

class File(Node):
    def __init__(self, name, bytes_):
        self.name, self.bytes_ = name, bytes_
    def size(self): return self.bytes_

class Folder(Node):
    def __init__(self, name):
        self.name, self.children = name, []
    def add(self, node):
        self.children.append(node)
        return self
    def size(self):
        return sum(child.size() for child in self.children)

root = (Folder("src")
        .add(File("main.py", 1200))
        .add(Folder("lib").add(File("util.py", 800))
                            .add(File("io.py", 400))))

print(root.size())   # 2400 — one call, whole tree
11

Bridge

two axes

Intent: split an abstraction from its implementation so the two can vary independently instead of multiplying into a class per combination.

Reach for it when
  • You have two independent dimensions — shape × renderer, message × channel.
  • Subclassing both would give you N×M classes.
Cost
  • More indirection up front for a payoff that only appears at scale.
  • Easy to over-apply on a small codebase.
python
from abc import ABC, abstractmethod

class Renderer(ABC):                       # implementation axis
    @abstractmethod
    def circle(self, r: int) -> str: ...

class VectorRenderer(Renderer):
    def circle(self, r): return f""

class RasterRenderer(Renderer):
    def circle(self, r): return f"pixels for r={r}"

class Shape:                               # abstraction axis
    def __init__(self, renderer: Renderer):
        self.renderer = renderer

class Circle(Shape):
    def __init__(self, renderer, r):
        super().__init__(renderer)
        self.r = r
    def draw(self): return self.renderer.circle(self.r)

print(Circle(VectorRenderer(), 10).draw())
print(Circle(RasterRenderer(), 10).draw())

Behavioral

07 patterns

These control how objects talk to each other — who decides, who listens, who remembers, and how a request travels.

12

Strategy

everyday

Intent: define a family of interchangeable algorithms and let the caller pick one at runtime.

Reach for it when
  • You have a growing if/elif chain choosing behaviour.
  • Policies differ per tenant, region, or plan.
Cost
  • Callers must know which strategy to pass.
  • For two branches, a plain function is simpler.
python
from abc import ABC, abstractmethod

class Pricing(ABC):
    @abstractmethod
    def total(self, amount: float) -> float: ...

class FullPrice(Pricing):
    def total(self, amount): return amount

class Seasonal(Pricing):
    def __init__(self, pct): self.pct = pct
    def total(self, amount): return round(amount * (1 - self.pct), 2)

class Member(Pricing):
    def total(self, amount): return round(amount - 5, 2)

class Cart:
    def __init__(self, pricing: Pricing):
        self.pricing = pricing
    def checkout(self, amount):
        return self.pricing.total(amount)

print(Cart(Seasonal(0.20)).checkout(100))   # 80.0
print(Cart(Member()).checkout(100))         # 95.0
13

Observer

everyday

Intent: let objects subscribe to changes in another object, so the publisher never needs to know who is listening.

Reach for it when
  • One event should trigger several independent reactions.
  • You want to add a listener without editing the emitter.
Cost
  • Control flow becomes indirect and harder to trace.
  • Forgotten subscriptions leak memory.
python
class EventBus:
    def __init__(self):
        self._subs = {}

    def subscribe(self, event, fn):
        self._subs.setdefault(event, []).append(fn)
        return lambda: self._subs[event].remove(fn)   # unsubscribe

    def publish(self, event, payload):
        for fn in list(self._subs.get(event, [])):
            fn(payload)

bus = EventBus()
off = bus.subscribe("order.paid", lambda o: print("ship", o["id"]))
bus.subscribe("order.paid", lambda o: print("email receipt", o["id"]))

bus.publish("order.paid", {"id": 42})
off()                                   # stop listening
bus.publish("order.paid", {"id": 43})   # only the email fires
14

Command

undo / queue

Intent: turn a request into a standalone object, so it can be queued, logged, retried, or undone.

Reach for it when
  • You need undo/redo, or an audit trail of actions.
  • Work must be queued, scheduled, or replayed.
Cost
  • One class per action — real overhead for simple apps.
  • Undo requires capturing enough state to reverse cleanly.
python
from abc import ABC, abstractmethod

class Command(ABC):
    @abstractmethod
    def execute(self): ...
    @abstractmethod
    def undo(self): ...

class AddText(Command):
    def __init__(self, doc, text):
        self.doc, self.text = doc, text
    def execute(self): self.doc.append(self.text)
    def undo(self): self.doc.pop()

class History:
    def __init__(self): self._done = []
    def run(self, cmd):
        cmd.execute()
        self._done.append(cmd)
    def undo(self):
        if self._done:
            self._done.pop().undo()

doc, history = [], History()
history.run(AddText(doc, "hello"))
history.run(AddText(doc, "world"))
print(doc)          # ['hello', 'world']
history.undo()
print(doc)          # ['hello']
15

State

state machines

Intent: let an object change its behaviour when its internal state changes, by delegating to a state object instead of branching on a status field.

Reach for it when
  • Behaviour depends on a status and the rules are growing.
  • Illegal transitions must be impossible, not just discouraged.
Cost
  • A class per state — heavy for 2–3 states.
  • Transition logic can scatter across state classes.
python
class Order:
    ALLOWED = {
        "pending": {"pay": "paid", "cancel": "cancelled"},
        "paid":    {"ship": "shipped", "refund": "refunded"},
        "shipped": {"deliver": "delivered"},
    }

    def __init__(self):
        self.state = "pending"

    def _move(self, action):
        nxt = self.ALLOWED.get(self.state, {}).get(action)
        if nxt is None:
            raise ValueError(f"cannot {action} from {self.state}")
        self.state = nxt
        return self

    def pay(self):    return self._move("pay")
    def ship(self):   return self._move("ship")
    def cancel(self): return self._move("cancel")

o = Order().pay().ship()
print(o.state)          # shipped
try:
    o.cancel()          # illegal from shipped
except ValueError as e:
    print(e)
Watch outThis table-driven form is the pragmatic version. Switch to real state objects only when each state carries its own data or many methods.
16

Template Method

skeleton

Intent: define the skeleton of an algorithm in a base class, letting subclasses override individual steps without changing the order.

Reach for it when
  • Several classes run the same sequence with different step bodies.
  • The order of steps is a rule you must not let callers break.
Cost
  • Inheritance coupling — the base class is hard to change later.
  • Fragile-base-class risk if hooks multiply.
python
from abc import ABC, abstractmethod

class Pipeline(ABC):
    def run(self):                     # the template — final by convention
        raw = self.extract()
        clean = self.transform(raw)
        self.load(clean)

    @abstractmethod
    def extract(self): ...

    @abstractmethod
    def transform(self, raw): ...

    def load(self, rows):              # hook with a sensible default
        print(f"loaded {len(rows)} rows")

class CsvPipeline(Pipeline):
    def extract(self): return ["a,1", "b,2"]
    def transform(self, raw): return [line.split(",") for line in raw]

class ApiPipeline(Pipeline):
    def extract(self): return [{"id": 1}, {"id": 2}]
    def transform(self, raw): return [r["id"] for r in raw]

CsvPipeline().run()   # loaded 2 rows
ApiPipeline().run()   # loaded 2 rows
17

Iterator

traversal

Intent: expose a way to walk a collection's elements one at a time, without revealing how the collection is stored.

Reach for it when
  • Callers should not depend on your internal data structure.
  • You want lazy traversal of a large or infinite sequence.
Cost
  • In most languages the language already gives you this — don't rebuild it.
  • Stateful iterators can be invalidated by mutation mid-walk.
python
class Tree:
    def __init__(self, value, children=None):
        self.value = value
        self.children = children or []

    def __iter__(self):                 # depth-first, lazy
        yield self.value
        for child in self.children:
            yield from child

root = Tree("a", [Tree("b", [Tree("d")]), Tree("c")])

for node in root:
    print(node)          # a b d c

print(list(root))        # ['a', 'b', 'd', 'c']

Chain of Responsibility

middleware

Intent: pass a request along a chain of handlers until one of them deals with it, so the sender never names a receiver.

Reach for it when
  • Request handling is a pipeline: auth → rate limit → validate → route.
  • Which handler applies is only known at runtime.
Cost
  • A request can fall off the end unhandled — always define a terminal case.
  • Debugging means following the whole chain.
python
class Handler:
    def __init__(self, nxt=None):
        self.next = nxt

    def handle(self, req):
        if self.next:
            return self.next.handle(req)
        return "200 OK"          # terminal case

class Auth(Handler):
    def handle(self, req):
        if not req.get("token"):
            return "401 Unauthorized"
        return super().handle(req)

class RateLimit(Handler):
    def handle(self, req):
        if req.get("burst", 0) > 100:
            return "429 Too Many Requests"
        return super().handle(req)

pipeline = Auth(RateLimit())

print(pipeline.handle({"token": "t", "burst": 5}))    # 200 OK
print(pipeline.handle({"burst": 5}))                  # 401 Unauthorized
print(pipeline.handle({"token": "t", "burst": 500}))  # 429 Too Many Requests

Which one do I need?

decision table

Start from the problem, not the pattern name. Find your symptom in the left column.

Your symptomReach forWhy
“My constructor takes 9 arguments”BuilderNamed steps beat positional parameters.
“I have a 40-line if/elif on a type string”Factory Method or StrategyCreating objects vs. choosing behaviour.
“I need to add retry/cache/logging to 12 methods”DecoratorWrap once, apply everywhere, no subclass explosion.
“This third-party SDK has the wrong shape”AdapterTranslate at the boundary, keep your code clean.
“Callers repeat the same 5-step setup”FacadeOne entry point over a messy subsystem.
“This object is expensive and often unused”ProxyDefer construction until first real use.
“I need undo / redo”CommandEach action becomes a reversible object.
“Status field with rules that keep growing”StateMake illegal transitions impossible.
“One event, five independent reactions”ObserverPublishers stop knowing about listeners.
“Request must pass auth → limit → validate”Chain of ResponsibilityComposable pipeline, runtime order.
“Same algorithm, different data source”Template MethodFix the order, override the steps.
“Two dimensions of variation (N×M classes)”BridgeSplit the axes so they vary independently.

When not to

read this

Patterns are a vocabulary, not a checklist. Every one of them adds indirection, and indirection has a price.

Signals you are over-engineering
  • An interface with exactly one implementation and no test double.
  • A factory that only ever returns one class.
  • Six files to add a field to a form.
  • You cannot name the change the abstraction is protecting you from.
What to do instead
  • Write the plain version first; extract the pattern when the second case appears.
  • Prefer a function over a Strategy class when there is no state.
  • Prefer composition over inheritance unless the order of steps is the point.
  • Delete abstractions nobody has needed for a year.
No patterns match that filter. Try “cache”, “undo”, “tree”, or “events”.
